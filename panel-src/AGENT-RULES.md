decisions that shape this folder stand (index: `docs/adr/README.md`); read the one that covers what you are about to touch. If you think a contract

## The layers: who may import whom

Every directory of `src/` is a layer. The arrow of imports goes one way; a file that imports against it makes a change in one place able to break
another with nothing to say so.

| Layer | What it is | May import |
|---|---|---|
| `src/main.js` | boot order: wires everything | everything |
| `src/core/` | pure logic and the DOM helpers: model, session, store, settings, diff, format, time, humanize, `h()` | `core/`, `i18n/`, npm packages |
| `src/i18n/` | the dictionaries (`es`, `en`) and `t()` | `i18n/` |
| `src/scene/` | the camera: engine, poses, clock, jump | `scene/`, `core/`, npm packages |
| `src/stage/` | the picture behind the sheet: sky, skyline, dial, beam | `stage/`, `core/`, `scene/` |
| `src/sound/` | the synthesised sound | `sound/`, `core/` |
| `src/ui/` | the shell and everything around the sheet: HUD, bar, keys, drawer, palette, help | `ui/`, `core/`, `i18n/`, `scene/`, `sound/`, npm packages; moments only through `moments/registry.js` |
| `src/moments/` | the stops: one file each plus a folder of parts | `moments/`, `core/`, `i18n/`, `ui/`, `scene/`, npm packages |

Between two moments there is no import at all (only `moments/registry.js`, the table of all of them, reaches into each). A moment reaches another
through `ctx` (for instance `ctx.go("procesos", opts)`), and what two moments both need goes to `core/` if it knows no moment, or to `src/moments/shared/` if it does (today it holds `armer.js`, below).

`test/arch.layers.test.mjs` enforces this on the import graph of `src/main.js`. It fails on any NEW edge that goes the wrong way, and also when a
known one disappears, so its list of debts (`DEBT`, 7 edges today: HOY's `actions.js` and `forms.js` imported by PROCESOS, the
dictionary index reading the store, and a few pieces in the wrong layer) can only shrink. Never fix a failure by adding a line to `DEBT`; move the
code. When you pay one, delete its line in the same commit.

## The moment contract

A moment is the module that draws one stop. It is the default export of `src/moments/<id>.js`:

```
{ id, mount(host, ctx), update(model, ctx), unmount(),            // required
  onKey?(actionId, row, event),                                   // a key of the stop or of a row; return true when it was the moment's
  arrive?(opts),                                                  // heard before the page travels here, with the opts of ctx.go(id, opts)
  drawer?(detail, card, ctx) }                                    // the stop's own page of an application (null keeps the common one)
```

- The shell keeps ONE moment mounted. `mount` builds the DOM once; `update(model, ctx)` patches it (never rebuilds the list); `unmount` removes every
  listener it added. The state of a mounted moment lives in the module (`let S = null`), so there is one instance at a time.
- A moment never reaches for the stage, the sound or the session by itself: it gets `ctx`, built in `src/ui/shell.js`. Its members are `t`, `tn`,
  `lang`, `sound`, `settings`, `session`, `flags`, `cursor`, `view`, `menu`, `open(jobKey, origin)`, `go(stopId, opts)`, `reduced()`, `now()`,
  `flat()` (the flat page, a phone, is in charge: no keys to talk about), `announce(text)`, `toast(text, ok, opts)`, `drawer { open, close, isOpen, step, reload, key }`, `model()`, `themeName()` and `chooseTheme(name)`.
  The moments also read four optional members the shell never supplies (`ask`, `openUrl`, `afterLink`, `lastVisit`); tests inject them.
- A big moment splits in three: `view` (pure: model in, rows out), `actions` (no DOM: which request each verb makes, with the session, the sound and
  the clock handed in so Node can test all of it) and `render` (builds the DOM once, patches it by parts). Look at `src/moments/cola/` as the model.
- What cannot be undone asks twice: the first press arms and says so, the second deliberate one goes through (`docs/adr/0006-two-presses-for-what-cannot-be-undone.md`).
  In an `actions` module that is `createArmer` from `src/moments/shared/armer.js` (`armer.press(rowId, verb)` answers `"armed"`, `"ignored"` or `"confirmed"`); never write
  the timing again by hand. `test/moments.shared.armer.test.mjs` fails if a new file does.
- A button that does something is `actButton` from `src/ui/act.js`, in every stop and in the drawer; its shape (display, size, weight, height,
  decoration) is written once, in `src/styles/actions.css`, and a stop's sheet may place it but never redraw it. Only a link (`<a>`) is underlined.
  `test/ui.act.test.mjs` fails if a module writes the classes `act` or `act-label` by hand, or a sheet draws the shape again.
- The words are in `src/i18n/{es,en}/`, never literals in a moment (a test scans `src/ui`); both languages keep the same keys.

**Adding or changing a stop touches more than one line.** Today, at least: `src/moments/<id>.js` and its folder; `MOMENTS` in `src/moments/registry.js`;
`STOPS_META` in `src/moments/shared/stops.js` (`registry.js` re-exports it); `STOP_IDS` and `MARKS` (the dial hour) in `src/scene/poses.js`; `ROOM_IDS` and the address pattern of `routeOfHash` in
`src/core/store.js`; `ROOM_IDS` (the arrival cue) in `src/sound/recipes.js`;
`WIRED` in `src/ui/wired.js`; `WORK` and the `stops` of each key in `src/ui/keys.js`; `NEWTASK_STOPS` and `JOB_STOPS` in `src/ui/shell.js`; the words

## Hard rules (a breach makes the work unusable)

1. **Stay in your lane.** Create and edit only the files your brief lists. Other agents work in the same tree at the same time on other files.
2. **Git and installs.** Your brief says whether you commit. If it does: commit with explicit paths (`git commit -m "..." -- <path> <path>`), never
   `git add -A` and never `git commit -a` (the tree holds other agents' work), and never push, merge or touch a remote. If it does not, run no git
   command that changes anything. Never use a bare `git stash` (the stack is shared). No `npm install` and no change to `package.json`,
   `package-lock.json` or `node_modules`; do not install anything; no network access.
3. **The page guard.** The built page may never contain what `guard.mjs` forbids: `FORBIDDEN` (30 strings, among them `innerHTML`, `outerHTML`,
   `insertAdjacentHTML`, `document.write`, `eval(`, `new Function`, ` style="`, `javascript:`, `<link`, `<iframe`, `import(`, `new Worker(`,
   `WebSocket`, `sendBeacon`) and `FORBIDDEN_PATTERNS` (`fetch` of an absolute address, `setTimeout` with a string, `createElement` of a script or an
   iframe). The bundle itself must not contain them either, so do not use a library API that does. Build DOM with
   `h()`/`sv()` from `src/core/dom.js`; set dynamic styles with `el.style.setProperty(...)` or classes. Never turn data into markup.
   `node build.mjs` and `node build.mjs lab <name>` enforce this on the bundle.
4. **Strict CSP.** `default-src 'none'; script-src 'nonce-…'; style-src 'nonce-…'; connect-src 'self'; img-src 'self' blob:; font-src 'self'; base-uri
   'none'; form-action 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'`. No inline event handlers, no inline `style=""`, no external
   fonts, images or scripts, no web workers. `tools/serve.mjs` sends exactly this policy, and `tools/cdp.mjs` turns every violation into a console
   error that `page.problems()` returns. A CSP violation is a failure.
5. **Real data only; fictional examples only in labs and the demo.** Never invent numbers that look like product data in the real UI. Never put real
   company names, people or emails anywhere.
6. **Do not claim what you did not run.** Report failures and uncertainty plainly. "It should work" is not a result.

## Style

- Plain ES modules (`export`/`import`), no framework, no TypeScript, no CSS-in-JS. Node 24 for tooling.
- Comment the *why* in a sentence where it is not obvious. No decorative banners, no emojis, no commented-out code, no TODO left behind (open
  questions go into your report).
- Names: short, concrete, English in code. User-visible text lives in the i18n dictionaries (Spanish and English), never as literals in moment or UI
  code (labs are exempt).
- Small modules with one job; a module you cannot summarise in a sentence is two modules.

## Tools you can use

- **Build:** `node build.mjs` (page to `dist/page.html`, checked by the guard), `node build.mjs --dev`, `node build.mjs demo --out dist/<yours>.html`
  (the page plus fictional data), `node build.mjs lab <name>` (needs `lab/<name>.html` containing `<script nonce="__NONCE__">/*__SCRIPT__*/</script>`
  and, for the shared CSS, `<style nonce="__NONCE__">/*__STYLE__*/</style>`; plus `lab/<name>.entry.js`).
- **Serve:** `node tools/serve.mjs <port>` serves `dist/` at `http://127.0.0.1:<port>/dist/<file>` with the production CSP. Use only the port your
  brief gives you, start it in the background and stop it when you finish.
- **Your own browser:** `tools/cdp.mjs` launches a private headless Chrome with `launch()`, `page.goto`, `page.eval(expr)`, `page.shot(file)`,
  `page.click(sel)`, `page.key`, `page.viewport`, `page.media`, `page.throttle(4)`, `page.metrics()` and `page.problems()`. Do NOT use the Playwright
  MCP tools: one browser is shared by every agent and they would collide. Browser tests start a Chrome each and hang under CPU contention: run them
  one file at a time, never several at once, and only when your brief asks.
- **Look at your own screenshots.** The Read tool shows PNGs. Put them in `dist/shots/<your package>/` and judge them as a harsh art director
  would. A screenshot you did not look at is not verification.
- **Foundations:** libraries enter only through `package.json` with an exact version and a row in `check-lock.mjs` (see `VENDORED.md`); fonts and
  icons only through `tools/fonts.mjs` and `tools/icons.mjs`. Agents on moments do not run them or change `package.json`.
- **Shell:** PowerShell is the safe shell on this machine; the Write, Edit, Grep and Glob tools are safer still.

## Before you say "done"

Run, from `panel-src/`, and put the output in your report:

1. **`npm run check`** (`tools/check.mjs`). It stops at the first failure and runs, cheapest first: the build with the guard (forbidden strings, the two
   global caps, and the budget of each area of the script), the layer test, `tools/check-bidi.mjs` (no bidirectional control character in the sources, the tests, the tools or these documents: write one as an escape, `"\u202e"`), and
   every test that needs no browser (`node tools/check.mjs --list` names them; the whole command took about 11 seconds on 2026-10-10). It adds nothing
   to the machine and does not touch git. It starts no browser, so it is safe to run while others work.
2. `node --test test/<file>.test.mjs` for the browser test files of what you touched, one file at a time, only when your brief asks (each starts its own
   Chrome; several at once hang under CPU contention). `npm run check:full` runs all of them in turn, for the owner or a quiet machine.

**Bytes.** `node build.mjs` prints the script by area (each layer, moment, dictionary and library) and refuses to write the page when an area, or the whole script,
grew past its margin over `budgets.json` (the larger of 3 KB and 5 % per area). If the growth is what you meant, run `node build.mjs --update-budgets`, commit
`budgets.json` and say why in your report; if not, the table says where it is. Never touch the two global caps of `guard.mjs`: moving them is a decision
recorded in `docs/adr/0005-budgets-and-their-history.md`, and the story's share is still open (`docs/adr/0009-where-the-story-lives-and-its-budget.md`).

`npm test` is the raw runner over every file, browser tests included, all at once; prefer the two commands above. There is no orphan-export check: a word-match
scan of `src/` against `src/`, `test/`, `lab/` and `tools/` found 37 exports that nobody imports on 2026-10-10; all were un-exported or deleted except 7 in
`src/moments/procesos/`, `src/moments/sistema/` and `src/moments/cola/render.js`, and a constant exported only for a test would need a baseline of harmless lines.

**Not wired to a hook yet, on purpose.** Nothing runs `npm run check` for you: no git hook, no Claude Code hook. A hook is standing configuration on
Gonza's machine and needs his yes (decision D8 of the architecture review). If he agrees, the two places are git's pre-push hook running
`npm run check` from `panel-src/`, and a Claude Code `Stop` hook in the project settings whose command is `cd panel-src && npm run check` (block the end
of the turn when it exits 1; keep it to the fast command). Until then, running the command is your job and its output belongs in your report.

## What to report (final message)

1. What you built: the files, one line each.
2. How you verified it: the exact commands and their results (test counts, sizes, frame times, screenshot paths).
3. Your honest assessment: what is good, what is mediocre, what you would redo with more time.
4. Deviations from the spec or the contracts, each with the reason.
5. Open questions or things another package must do because of your choices.

Keep the report under 600 words. Facts, not marketing.
